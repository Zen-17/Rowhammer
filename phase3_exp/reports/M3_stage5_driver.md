## 1. 空 burst 写入 — PASS

M3 Cell 的 `HOST_ATK` 原来对物理邻居做一次写，数据是默认的空 burst。区域换行后，这个物理行可能正放着别的逻辑数据，于是结果被改掉，同时模型翻转数和 ECC 都是 0。

现在同一次锤击改成对这个物理行的读。读仍会在开页策略下先激活、排空时再预充电，所以每步仍是一次激活；读不会把新 burst 存进去。`HOST_BG` 仍按原样写逻辑行 200–231 和 300–315，这些行不在 W2 或 DEC 的计算行里。邻居选择、攻击上限和停锤条件没动。

隔离测量：

- 对已有数据的邻居做 `HOST_ATK` 读，原 burst 不变。对数据行自己做 `HOST_ATK` 读，也不变。
- 同一次诊断里，对这个物理行做空 burst 的 `HOST_ATK` 写，burst 改变。这条写只出现在诊断里，不在 Cell 的锤击循环里。
- 一次 `HOST_ATK` 读使邻居扰动 +1。

同一组锁定参数（A1、缩放 0.0625、种子 20261122、逻辑受害者 640）再跑一遍：锤击仍是 16002 次，模型翻转 0，CE 0，UE 0。逻辑行 640 从物理 640 换到物理 703，结果与主机计算一致，计算错误 0，没有错误提交。上一轮同样的参数在空 burst 写下有 3 个错误 burst。

## 2. 地址与错误来源 — PARTIAL

逻辑行、物理行和生命周期对得上。不设边界变量时，锤击目标是结果逻辑行 640，开打前物理行也是 640。换行之后物理行变成 703，逻辑读仍得到原来的结果。`HOST_ATK` 使用物理地址，不经过逻辑映射；`HOST_BG` 和内核操作数使用逻辑地址，再映射到当前物理行。

三种数据变化是分开的：

| 来源 | 模型翻转 | ECC | 结果 |
| --- | ---: | --- | --- |
| 直接注入一个数据位，逻辑行 0 | 0 | CE 1 | 计算错误 0，不重放，结果正确 |
| 直接注入两个数据位，逻辑行 1（tile 4） | 0 | UE 1 | 恢复掩码 16，提交失配 0 |
| 扰动模型，16002 次激活 | 0 | CE 0，UE 0 | 计算错误 0 |
| 诊断中的空 burst 写 | 不经过模型 | 不经过 ECC | 该 burst 改变 |

模型翻转这一路在锁定阈值下没有跨过第一级，所以没有出现“模型翻转 → 存储位 → ECC → 恢复”的实测样本。验收标准不是制造一次翻转，阈值没有下调。数据位仍由 `consider` 先在第 0 列尝试；校验位仍会被战役注入器拒绝。

战役脚本的目标没有改。无攻击对照仍读到 W2 的 768 和 DEC 的 2432。这两行不在 W2 的 640–651，也不在 DEC 的 2000、2128、2256、2384 或 GEMV 的行 0–65。因此驱动器不再用普通写制造错误，但正式战役指定的锤击行仍然不是被计分的数据。

## 3. 计费 — PASS

`commandOnlySwap` 仍是关的。一次真实激活的扰动是 +1，`noteSwap` 是 +2。一对行的估计时间是 2568 周期：每行 32 个 burst，读行 `14+31×4+5+14`，写行 `10+31×4+16+14`，一个 bank group 的四个 bank 串行，四个 group 重叠。这个数在队列待处理命令为 0 时加入，扰动增量是 0。

它和真实命令调度的差别是：换行、重映射和清扫回写没有插入命令队列。真实激活只来自已经进队列的读或写，时间在 `drain` 里。再把换行插进队列会多一次激活，扰动会叠到 `noteSwap` 的 +2 上。只有 bank 0 记录这一对，2568 已经包含 16 个 bank，不会再乘 16。清扫回写仍是发现它的那次读之外，每个码字加一个 `tCCDL`。这次冒烟清扫次数是 0，清扫周期是 0，没有另一笔清扫账。

这次换行计费是 7390704 周期，等于 2878 对乘 2568。上一轮空 burst 写时是 2844 对。步数都是 16002，差别来自读命令和写命令的时序不同，区域周期因此略有错开。每一对仍然只计一次，不是按 bank 重复计。

无攻击时 NONE 和 OURS 的 PIM 命令数都是 7059。
