# M3 故障模型与实验设计审计

本轮没有改攻击参数、故障阈值、防护机制或 G4 标准，也没有新跑大规模实验。证据来自当前 Cell 代码、`results/m3/datapath_stage5_driver/driver.json`，以及旧战役汇总 `results/m3/E5_campaign_summary.csv`。旧战役的 O6 不能当作 PIM 输出错误。

## 1. 原有实验对象还是否成立

不成立。扰动模型本身可以保留，实验对象不能。

W2 的计算数据是逻辑行 0–11、128–139、256–267、384–395、512–523，结果是 640–651。DEC 的计分链是逻辑行 2000、2128、2256、2384。DEC 的 GEMV 使用行 0 附近到约 64–65，不进入 2384。这些逻辑行经区域映射变成当前物理行；换行后逻辑行不变，物理行改变。

原战役把 `PHASE3_BOUNDARY_VICTIM=1` 固定在脚本里。W2 锤 768，DEC 锤 2432。768 距结果段 640–651 有 117 行，2432 也不是 2384。旧单元还在这些行上写了主机图案，并把这一列的图案当作对错。内核的 RELU 不读这些行。因此旧汇总里的翻转和 O6 描述的是图案行，不是 PIM 结果。

当前 Cell 在不设这个变量时，锤的是结果逻辑行，并在每一步取它的当前物理行。`driver.json` 里逻辑行 640 从物理 640 换到物理 703，逻辑结果仍与主机计算一致。这条路径只覆盖结果的第一行、bank 0。W2 其余 11 行结果、输入行，以及 DEC 的 2000/2128，都不是锤击对象。区内中间行的邻居是前一行，所以物理行移动之后，被激活的不一定还是结果数据的邻居。

`scripts/run_m3.py` 仍设置边界受害者。正式战役若按这个脚本启动，打的仍是旧对象。

## 2. 零翻转从哪里来

当前这一次零翻转不是 ECC 或恢复生效。`driver.json` 的 A1、缩放 0.0625、种子 20261122：锤击 16002 次，模型翻转 0，CE 0，UE 0，清扫 0。没有错误进入译码器。16002 等于初始物理行的 `firstThreshold × 2.6 + 64`，也就是步数上限，不是提前发现翻转后停止。

同一缩放下，旧战役汇总里的模型是会放进翻转的。W2、A1、0.0625：

| 方案 | 样本 | 平均翻转 | 旧标签 |
| --- | ---: | ---: | --- |
| NONE | 100 | 2.00 | O6 100/100 |
| OURS | 300 | 1.04 | O6 0/300 |
| PARA | 100 | 0.00 | O1 100/100 |
| REACT | 100 | 2.00 | O3 100/100 |

这些翻转打在图案行 768 上，只能说明锁定阈值下模型能够放置数据位，不能说明 PIM 结果被保护或被打中。PARA 的 0 来自它自己的邻行刷新，不是这次新 Cell 的现象。DEC 的 NONE 同样是平均 2 次翻转。

新 Cell 这次为 0，和三件事叠在一起：

- 防护会改扰动累计。OURS 换行调用 `noteSwap`，把该物理行的扰动清掉。这次换了 2878 对，区域级别到 1，受害者物理行从 640 移到 703。停锤看的是当前物理行的 `emitted`。行被换走以后，累计不再留在被检查的那一行上。这可以造成达不到阈值，但它和下面两条混在一起，不能单独当成“防护有效”。
- 模型有放不进位的口。`consider` 先在第 0 列尝试数据位；没有码字时 `injectRawDataBit` 失败，校验位被 `injectRank` 拒绝。失败不增加已放置翻转数。这次停在步数上限，说明被检查的那一行 `emitted` 仍是 0，所以这一次不是“越阈以后没写进码字”。
- 覆盖不够。只有 OURS、一个种子、一个 bank、结果的第一行。新 Cell 上没有配对的 NONE 锤击。没有这组对照，就不能把 0 分成“换行清掉了扰动”和“这一行本来也不会越阈”。

阈值本身没有高到不能翻转。下限是 `2 × 14531 × 0.0625 = 1816.375`。旧 NONE 在这个缩放下放置了约 2 次翻转。不要为了看到翻转去改 HC、缩放或上限。

## 3. 两类实验分别能支持什么

应分开评价，不要合成一张 O1–O6 表。

直接注入碰的是选定逻辑行上已经写入的码字，不经过扰动阈值。现有诊断支持这些功能结论：单个数据位产生 CE，结果仍正确，模型翻转数不增加；两个数据位产生 UE，tile 4 被单独恢复，提交失配为 0；缺检查点时不提交。它不支持“RowHammer 打到了计算数据”“预防降低了翻转”或“OURS 的 O6 低于 NONE”。

RowHammer 扰动实验才能支持攻击下的结论：邻居激活是否改变 PIM 输出、换行或 ECC 是否改变这个输出、以及这些动作的周期。当前新 Cell 的一次 OURS 锤击只支持一个窄陈述：在该种子和缩放下，模型没有放置翻转，输出与主机计算一致。它不支持防护有效，因为没有同一路径上的 NONE 对照，也因为战役脚本的锤击行仍不是计分数据。

旧战役的 O6、吞吐和 G4 数字继续不能用。G4 原标准保持不变，状态保持 PENDING。

## 正式战役的启动条件

现在不能启动。要同时满足：

1. 锤击对象改成计分逻辑行的当前物理位置，并写明 768 和 2432 不再作为受害者。这是实验对象的选择，不是阈值或防护参数。
2. 在新 Cell 上先做一对小对照：同一工作负载、同一缩放、同一攻击和种子，只比较 NONE 与 OURS 的已放置翻转、CE/UE 和结果是否一致。放在新目录。NONE 没有放置翻转时，0 翻转仍不能解释成防护有效，战役继续暂停。
3. 直接注入维持单独的功能表，不进入 O1–O6。
4. G4 仍由原标准判定。e5c、fig6、fig7 不覆盖、不重画。
