## 1. 故障模型与计算路径 — FAIL

W2 的真实数据是 12 行一段：0–11、128–139、256–267、384–395、512–523，结果是 640–651。DEC 的逐元素输入和结果各占一行：2000、2128、2256、2384。DEC 里的 GEMV 读权重行 0 起、列按 32 换行，写到约第 64–65 行，和 2000 以后的逐元素行不相交。

战役脚本仍指定边界受害者。这次无攻击对照读到的锤击行是 W2 的 768、DEC 的 2432。768 不在 W2 的任何一段里，2432 也不在 DEC 的逐元素行或 GEMV 行里。不设这个环境变量时，Cell 锤的是结果行 640，物理行在换行前也是 640。攻击参数没有改，所以战役目标和计分数据仍然不是同一处。

锤击本身是对物理邻居的一次 `HOST_ATK` 写，不是只发激活。区域大小是 64 行。640 和 703 是第 10 区的两端，邻居落在区外；区内的中间行会选前一行。正式冒烟里逻辑行 640 从物理 640 被换到物理 703，中途经过区内的行。邻居写会把一个空 burst 写进当时占用该物理行的数据。这次模型翻转数是 0，ECC 的 CE 和 UE 也是 0，但结果有 3 个 burst 和主机计算不同，并且被提交了。这 3 个 burst 不是 RowHammer 翻转。

因此现有攻击没有始终作用在计算数据的当前物理位置上，也不能把它当成“只扰动、不改写”的激活。战役在选定锤击目标之前不能启动。

## 2. 完整错误传播 — PARTIAL

两条路径分开记。

直接存储注入不经过扰动模型。W2 逻辑行 1、列 0 的两个数据位：`direct_inject=true`，模型翻转 0，UE 1，计算错误 1，重放后恢复掩码是 16（tile 4），提交失配 0。DEC 逻辑行 0 的两个数据位：模型翻转 0，UE 3，计分错误 0，没有重放，结果与 `applyRelu(left+right)` 一致。行 0 是 GEMV 读到的权重，不是 2384 的输入。

真实扰动用的是锁定参数：A1、缩放 0.0625、种子 20261122、受害者逻辑行 640。`direct_inject=false`。锤击 16002 次后模型翻转 0、潜伏翻转 0、CE 0、UE 0、模型清扫 0。停锤条件读的是 `flipsOn`，这次没有翻转，所以没有进入 ECC、分级防护之后的恢复。上面的 3 个错误 burst 发生在这条路径上，但来源是邻居写，不是 `consider` 放入的位。没有把阈值或受害者改到能产生翻转的值。

数据位和校验位的覆盖没有改。`consider` 先在第 0 列尝试数据位 0 到 63；校验位只出现在随后的随机抽取里，战役注入器 `injectRank` 对校验位返回假，所以正式模型放不进校验位。Stage 5 的 `fault.json` 已经量过：直接 `injectRawParityBit` 能改校验位，模型路径不能。

## 3. 工作负载覆盖 — PASS

W2 有 48 个 tile，DEC 的逐元素链有 1 个 tile。检查点按 tile 保存全部版本 0 输入。每个 tile 单独 `planOp`，观察的行是基行加 `tileRowOffset`。只观察基行时，tile 4 完不成；观察基行加偏移后可以完成。

选择性恢复用的是 tile 4，不是第 0 列的 tile 0。双比特注入后只恢复了这一个输入 tile，重放把它的结果改回，提交失配为 0。没有整段重放。

GEMV 不写入 DEC 的计分依赖。行 0 上的双比特产生了 3 次 UE，ADD/RELU 没有被重放，2384 的结果仍然正确。所以 GEMV 没有放进这条计分账本；放进去也不会改变这次计分，漏掉的不是 2384 的计算。

无攻击时 W2 的 PIM 命令数仍是 7059，和 Stage 5 的 Cell 相同。账本扩大没有改变内核本身。

## 4. 性能与扰动 — PASS

默认没有打开 `commandOnlySwap`。一次真实 `HOST_ATK` 写使邻居扰动增加 1。`noteSwap` 使邻居扰动增加 2。把 2568 个周期加进计数时，队列里的待处理命令是 0，扰动增量为 0。

因此换行时间不再发一次 ACT。再发的话，真实激活的 +1 会叠在 `noteSwap` 已经记入的 +2 上，等于把同一次换行的扰动算两次，也会改故障模型。现在的分工是：扰动只由 `noteSwap` 记，16 个 bank 的开页时间由这一对行的 2568 周期记一次。只有 bank 0 把这一对放进计费列表，不会按 16 个 bank 再乘。清扫回写仍是发现它的那次读之外，每个码字再加一个 `tCCDL`（4 周期）。

冒烟里 OURS 的换行计费是 7303392 周期，等于 2844 对乘 2568。这些换行来自锤击激活累计达到区域周期后的 `flush`，不是 ECC。NONE 不走这条换行。内核命令数两边仍相同，恢复才增加 OURS 的重放命令。

## 冒烟

一次端到端是上面的 A1 Cell，不是 4800 次战役。锁定参数下模型没有产生存储翻转，ECC 没有事件，恢复没有启动，3 个被邻居写改掉的 burst 被当成结果提交。直接注入的 tile 4 路径则走完了存储翻转、UE、选择性恢复和正确提交。

正式战役、fig6、fig7 和 G4 都不进入下一步。要启动战役，先得单独决定锤击目标：768/2432 不是计算数据，而结果行 640 在换行之后又会让邻居写打进活数据。这次没有替这个决定改攻击。
