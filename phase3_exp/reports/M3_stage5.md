## 1. 战役集成 — PASS

`runM3Cell` 是正式 Cell 的函数。它做了这些替换：

- 操作数按逻辑行预加载。W2 的结果行是 640，DEC 的结果行是 2384。比较对象是主机按同一输入算出的结果，不是写进 DRAM 的 `0x40` 图案，也不会把图案写回。
- 剖面是已有的 `LOCAL_VISIBLE`。CE 只从译码经 `phase3SetCeHook` 进入 `noteCe`。Cell 里不再出现 `flipsOn` 之后调用 `noteCe`。
- 清扫是 `CORRECTED` 之后的 `writeLegal`。M3 把 `undoModelBits` 设为假，换行不再调用 `scrubSingleBits`。
- 恢复是 B2。检查点只保存 tile 0 的输入。UE 才重放 `executeEltwiseTiles`。发布前用 `Gate::hold` 绑住结果行；没有信任输入时 `poison`，不发布。
- 攻击锤击仍用 `HOST_ATK` 打当前物理邻居。停锤条件仍是模型的 `flipsOn`，这只决定攻击长度，不进入防护。

`cell.json`：

- 无攻击时 W2 结果与主机计算一致，NONE 和 OURS 的 PIM 命令数都是 7059，模型清扫次数为 0。计分行是 640。
- 在逻辑行 0 注入一个数据位：CE=1，模型翻转数=0，结果仍然正确，没有重放，SECDED 回写 1 次。防护没有读取模型计数。
- 注入两个数据位：计算错误 1，UE=1，恢复 1 个输入 tile 并重放，提交失配为 0。
- NONE 在同样的双比特下结果不正确，并且把这个错误结果提交出去，没有重放。
- DEC 无攻击的逻辑行 2384 与 `applyRelu(left+right)` 一致。

## 2. 错误注入重新评估 — PASS

故障模型代码没有改。`fault.json` 核对的是它在新数据路径上的行为。

- 战役注入器 `injectRank` 对校验位直接返回假，存储的数据和校验位都不变。直接调用 `injectRawParityBit` 只改校验位；`injectRawDataBit` 只改数据位。模型的 `consider` 仍先在第 0 列尝试数据位 0 到 63，校验位只出现在随后的随机抽取里，而战役注入器会拒绝它。
- 数据位在被真实读取并清扫之前一直留在码字里。打开清扫时，一次逻辑读产生 CE=1、区域级别 1，原始数据恢复，再读不再产生 CE。`OURS-SCRUB` 关闭回写后，原始数据保持翻转，第二次读的 CE 继续增加。
- 换行使用 `exchangeRows`，数据和校验位一起搬到新的物理行。这次诊断里目标行是 1，源码字消失。逻辑读仍得到原数据，并产生 CE。模型的 `flipsOn` 不随这次存储注入增加，换行也不改这个计数。
- 注入器没有调用 `noteCe` 或 `scrubSingleBits`。模型清扫次数为 0。区域升级来自译码报告。

因此注入器不会把比特位置或翻转名单交给 ECC、清扫和恢复。模型计数和码字存储是两套状态：存储注入不会增加 `cumulativeFlips`，模型里已记录的翻转也不会在 `exchangeRows` 时跟着搬到新行。

## 3. 性能与公平性 — PARTIAL

检查点写回和内核重放走的是真实事务，周期由 `drain` 测得。一次 128 burst 的检查点写回是 280 周期。一个 ADD tile 的重放是 790 周期、103 条命令；NONE 和 OURS 这条命令数相同。正式 Cell 里无攻击的 W2 两边都是 7059 条 PIM 命令，外部背景写和锤击循环也是同一段代码。

换行、备用行重映射和 SECDED 回写没有插进命令队列。再发一次 ACT 会在 `noteSwap` 已经给邻居加的 2 次扰动之外再加扰动，等于改了故障模型。因此这三项只把对应的开页命令时间加进周期计数：

- 一对行、16 个 bank：每行 32 个 burst，读开销 `tRCDRD + 31×tCCDL + tRTPL + tRP`，写开销 `tRCDWR + 31×tCCDL + tWR + tRP`，一个 bank group 的 4 个 bank 串行，其余 group 重叠。一对数是 2568 周期。旧的 bank 0 `4×47` 是 188。
- 升到 L2 时的备用行搬迁再记 2568，诊断里两次合计 5136。
- 已经发生的读本身在 `drain` 里。额外的回写按每个 burst 一个 `tCCDL`（4 周期）计。1 次码字回写记 4 周期。

这三项没有占用命令总线，也不会推迟已经排队的请求。队列在换行点本来是排空的，所以加上的是空闲总线上这些命令本身的时间。

- 锤击循环这次没有跑。诊断用的是 `NO_ATK` 加直接存储注入。停锤仍读取 `flipsOn`，只用于攻击长度。
- 账本只声明每个内核的 tile 0。模型的前 64 次翻转都在第 0 列，正好落在这个 tile。更后面的列不在恢复账本里。DEC 的 GEMV 仍会执行，但不在 B2 账本里；无攻击时它没有改变第 2384 行。
- 换行、重映射和清扫回写的周期没有进入命令调度器。
- G4 的两条原标准都还没有用这条新 Cell 重测。fig6、fig7 和 4800 次战役都没有启动。
